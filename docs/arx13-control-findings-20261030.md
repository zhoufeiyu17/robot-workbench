# ARX13 控制平顺性问题阶段总结

截至 2026-10-30｜维护：控制研究任务｜后续完成新对照、核实固件路径或改变基线时更新。本文提炼本机证据，完整过程见[控制状态记录](/Users/wujie/Developer/work/anyverse/github/zhoufeiyu17/robot-workbench/docs/control-runtime-status.md)。

**目前确认的是：实际反馈存在反复快慢变化，静态到位也有偏差；尚未找到唯一根因。降低参考节点频率、局部调整 D、小幅方向前馈，都没有证明能稳定消除这种起伏。当前仍保留默认增益的 base-v1，没有晋级新的调参方案。**

## 1. 研究对象与当前基线

目标是运动与停位平顺、没有非预期振荡，静态到位进入一个位置反馈码以内（约 **0.02186°**）；运动允许滞后。统一使用 ARX13 的同一完整 **1.5× 轨迹**，主段约 35.33 秒，随后停位、以 0.1 rad/s 正常回零。

双臂 base-v1 按 J1–J6 排列：

- **P：80 / 70 / 70 / 30 / 30 / 20；D：2 / 2 / 2 / 1 / 1 / 0.7。**
- 上层积分 I=0，无学习前馈；保留 SDK 名义重力补偿及 0.8 rad/s 速度保护。电机内部电流环仍有自己的 PI。
- J1–J3 为 EC，J4–J6 为 DM。EC 沿用当前旧单位约定；DM 已完成保持实际输出不变的单位整理，尚不等于真实力矩或重力模型已标定准确。

控制链为：

```text
连续目标曲线 → 100/30 Hz参考节点 → 约50 Hz补给未来窗口
             → SDK名义500 Hz输出 → 电机固件PD与电流环
```

CAN 实测每关节发送间隔中位数为 **2.053 ms，约 487 Hz**。参考节点、窗口补给、SDK 输出和电机内环是四个不同层次；电机内环实际频率及速度估计路径尚未核实。

## 2. 实际看到了什么

1. **速度脉冲伴随位置推进不均匀。** 曲线呈现“落后积累，再追赶”的反复变化，不能仅解释为速度显示噪声。但角度与速度可能共用编码器，尚不能据此排除编码器误差，也不能代替外部测量。
2. **D 在速度峰值附近主要表现为制动。** 用 CAN 重建近似关系 `P项=Kp×位置误差、D项=Kd×速度误差`，左 J1/J5/J6 的 D 变化主要来自反馈速度；28–30 秒片段内，反馈侧变化 RMS 约为指令侧的 23–26 倍。这说明 D 项如何变化，**不能证明 D 或估计延迟没有参与振荡形成**。固件内部细分反馈、滤波与采样时刻仍未知。
3. **静态精度尚未达标。** 本轮左 J1 仍有 3–4 码误差，部分其他关节达到 20–30 码；不能称为全臂已达到“一格内”。
4. **当前起伏不依赖一次明显通信故障才能出现。** 七轮对照累计约 831 万 CAN 帧、零 socket 丢帧，主段/保持反馈 RPC 最大约 15.23 ms，起伏仍存在。这削弱了“大停顿是全部根因”的解释，但不排除更细的时序影响。

图中加速度来自速度差分，并非传感器直接测得；20 Hz 离线平滑仅用于看趋势，没有加入控制器。同一时刻的角误差包含允许的跟踪滞后，不能直接当作空间路径偏离。

## 3. 当前已尝试的对照及结果

### ARX13：左 J1 的 D 与方向前馈

固定 P80，其他关节不变，完成 **基线→D低→基线→D高→基线→方向前馈→基线** 七轮完整 1.5×。下表是递送段相对相邻基线的变化，负数表示该指标下降。

| 单变量 | 原始速度误差 RMS | 用100 ms位置位移计算的速度误差 RMS | 解释 |
| --- | ---: | ---: | --- |
| D：2→1.5 | +9.44% | +15.55% | 降 D 未改善这段起伏 |
| D：2→2.5 | −10.80% | −4.82% | 原始速度改善，但位置推进指标收益接近基线自然波动 |
| D2＋小幅方向前馈 | −1.33% | +9.65% | 平均落后减小，起伏未消除 |

三种干预的同拍角误差峰峰值均未下降，静态误差均为 4 码。方向前馈峰值约为基线外增加/减少 3 个 CAN 前馈码，平均落后减少 **0.01616°**，与 `Δ前馈/Kp` 准静态估算 **0.01985°** 的方向一致。它证明小幅输出会改变平均偏差，尚未证明该补偿能解决平顺性。

每种干预只有一轮、前后穿插基线，属于筛选，不能当作重复性已验证。

### ARX13：100 Hz→30 Hz 参考节点

使用同一连续 q/dq/ddq 曲线，只改变主段节点密度；准备、回零、PD、原生 SDK 频率不变。

| 实测项目 | 100 Hz | 30 Hz |
| --- | ---: | ---: |
| 参考节点间隔 | 10.000 ms | 33.333 ms |
| 窗口补给间隔中位数 | 21.551 ms | 21.767 ms |
| 每关节 CAN 发送间隔中位数 | 2.053 ms | 2.053 ms |

两轮均完成主段、停位、回零和录像，零 socket 丢帧。**速度起伏仍存在，各轴峰值有升有降，没有建立整体改善结论；默认恢复 100 Hz。** 30 Hz 对原连续曲线的线性插值误差上限约 0.00190°，这是输入近似误差，不是真机精度。此次没有测试降低 SDK 原生 500 Hz 或电机内环频率。

### ARX13：30 Hz只给位置，让SDK自行算速度

随后完成一轮同轨迹实拍：适配层只向原生轨迹接口提供位置/时间，由SDK按约50 ms窗口差分重算速度，准备与回零仍保留原q/dq方式。**起伏仍存在，没有一致改善。** 相比上一轮30 Hz，递送段J1原始速度误差RMS降2.54%、位置推进指标降1.54%；J3分别降4.76%、升8.12%，J1静态仍4码。此接口还会重连未来窗口，不能将全部变化归于速度公式。单次对照尚未晋级，默认配置已恢复。

### 历史 ARX6：哪些路走过，但不能直接沿用

| 已尝试方向 | 可保留的认识与边界 |
| --- | --- |
| 参考平滑、q/dq连续、窗口与结束转保持；100→200 Hz | 修复过指令链路问题；200 Hz 两次表现一好一坏，没有稳定收益，不能认为提高节点率就能消抖 |
| P/D、积分参数及暂停累加对照 | 做过，并非从未调 I；结果依赖姿态和工况。早期 J3 高 P 主要在1×研究，J2 P400主要来自小角度/静态测试，不代表整段1.5×或ARX13适用 |
| 重力、单位换算、静态前馈剂量、多姿态辨识 | 特定 J2 工况增加输出可将2码残差降至1码、撤回后恢复，支持静态偏差受补偿影响；不足以把动态起伏全部归于重力 |
| J3周期前馈、任务空间协同、学习前馈 | 有局部收益，但幅相及重复响应不够稳定，尚无可直接迁移的稳定方案 |

历史 ARX6 J3 曾检出约 **0.72°空间周期**，随运动速度改变时间频率；它不是已经证实的 ARX13 J1 周期。原生循环降频、内环速度滤波/陷波也不能列为当前已验收有效的措施。

## 4. 当前怀疑点：证据到哪一步

| 假设 | 已有依据 | 缺什么才能进一步判断 |
| --- | --- | --- |
| 摩擦、传动弹性或随关节角变化的扰动 | 反复落后/追赶；方向前馈改变平均偏差，却未消除起伏 | 同角度、不同方向/速度的相位对齐；检查周期是否跟随角度 |
| 速度估计噪声/延迟与 D 耦合 | D主要随反馈速度变化；调D能改变速度指标 | 电机实际估计/滤波路径、延迟，或独立外部运动测量 |
| P/D与机械耦合不匹配 | 影响响应；不同关节表现不同 | 在同一整段轨迹上取得可重复的单变量收益，不能仅看某个速度尖峰 |
| 重力/负载慢偏置叠加方向效应 | 静态残差及前馈响应支持存在保持输出缺口 | 多姿态、双向重复辨识；先区分静态偏差与动态起伏 |

本机寄存器已读回：EC 的 Kt=1.4、P范围0–500、D范围0–5，电流 PI=0.0359/250；DM 为 MIT 模式，读到 `I_BW=1000、V_BW=40`。**V_BW 的单位、滤波形式及是否作用于 MIT 的 D 支路仍未确认，不能直接称为“40 Hz滤波”，也不能拿 DM 参数解释 EC J1。** 尚无证据判定必须更换硬件，亦无证据保证仅靠软件调参即可解决。

## 5. 初步结论与后续顺序

当前更合理的工作假设是：**负载/摩擦/位置相关扰动与闭环响应共同造成不均匀跟随，静态补偿不足是另一条需要单独处理的线。** 这是待验证的解释，不是已定位的根因。现有证据不支持把问题简单归结为“100 Hz太高”“D太大”或“全是重力模型偏小”。

1. **先用已有全段与回零数据区分角度相关、时间相关起伏。** 判断波峰是否在相同关节角重现，再决定辨识机械周期项还是控制动态。
2. **补齐电机内部速度估计/滤波证据。** 只有确认参数真正作用到目标内环后，才设计对应滤波或阻尼对照；必要时用外部观测区分编码器起伏与真实运动。
3. **把静态平衡与动态平顺分开优化。** 针对有证据的机制做有界、可重复的单变量干预，所有候选回到同一完整1.5×验收。

执行可靠性问题另行处理：启动清单误绑定动态文件、相机重启后旧客户端未刷新绑定。历史调度/IO/Guard修复提升了可靠性，但不能代替运动平顺性验收。

最近一次已核验收尾状态为：SDK正常释放、默认100 Hz恢复、原数采网页恢复idle。本次只整理文档，没有重新核验实时设备状态或执行控机。
